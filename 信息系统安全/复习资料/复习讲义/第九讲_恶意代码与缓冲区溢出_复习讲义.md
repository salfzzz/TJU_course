# 第九讲：恶意代码与缓冲区溢出——复习讲义

> 依据四份第九讲课件整理：**总册**《第9讲 恶意代码攻击》（97 页）、**病毒册**《计算机病毒》（44 页）、**溢出册**《缓冲区溢出》（34 页）、**图片册**《恶意程序攻击》（69 页，主要为整页图片，内容与总册第 28–96 页对应）。`[总 16]` 等表示原 PPT 页码。复习顺序：先区分恶意代码类型，再掌握病毒结构与检测，最后理解缓冲区溢出的内存错误和防护。

## 一、考点地图

1. **恶意代码的范围与分类**：病毒、蠕虫、木马、陷门/后门、逻辑炸弹等，判别关键为“是否自复制、是否依附宿主、怎样传播、目的是什么”。[总 2–3、27–29；病毒 3]
2. **病毒**：定义、六项特征、四种存在状态、寄生与感染方式、多维分类、引导/感染/表现三模块。[总 4–15、30–59；病毒 4–24]
3. **病毒检测与防护**：长度、标志/特征码、校验和、行为监视、模拟/分析，各自适用范围与局限；强化配置和使用习惯。[总 15、63；病毒 26–34]
4. **蠕虫、木马和后门**：独立网络传播、扫描/攻击/复制；伪装植入与受控运行；秘密入口及持久化。[总 16–26、60–96]
5. **缓冲区溢出**：五类内存区域、栈帧、ESP/EBP/EIP、越界写入和后果、NSR/RNS/RS 示意、防御分层。[溢出 2–34]
6. **全部显式题目**：病毒册第 35–42 页八道选择题、第 44 页四道思考题；溢出册的原理和防范简答点。[病毒 35–44；溢出 24、33–34]

## 二、先分清五类恶意代码

**恶意代码**是未经授权而执行破坏、窃取、干扰或控制等行为的软件或代码片段，范围大于“计算机病毒”。[病毒 3；总 3]

| 类型 | 是否通常自复制 | 依附与进入方式 | 核心识别句 |
|---|---|---|---|
| **病毒 Virus** | 是 | 依附宿主文件、引导区或可执行内容，经宿主执行/感染传播 | **寄生 + 自我复制/感染** |
| **蠕虫 Worm** | 是 | 作为独立程序，通过网络主动寻找并传播到其他主机 | **独立 + 网络主动传播** |
| **木马 Trojan** | 通常否 | 伪装成正常软件、附件或安装包，被投放/运行后受控或实施恶意行为 | **欺骗/植入 + 隐藏目的** |
| **陷门/后门 Backdoor** | 通常否 | 在系统或程序留下非公开入口，绕过正常认证/访问路径 | **秘密入口 + 便于再次进入** |
| **逻辑炸弹等** | 视类型而定 | 满足指定条件后触发；其他成员还有下载器、间谍软件、勒索软件等 | 按**具体行为**判断 |

[总 3、16、19、24–29、60、75–76、87–96] 一个真实样本可以同时具有多种属性，例如蠕虫把木马投放到新主机；**分类是特征分析工具，类别不是互斥标签**。课件把“木马必须靠人植入”写得过绝对，后文自己又列“通过病毒或蠕虫传播”；答题可写“木马**自身通常不自传播**，但可被其他机制投放”。[总 19、75、82]

**易混三句**：病毒“感染宿主文件”；蠕虫“复制自身到联网主机”；木马“诱骗或被投放后运行”。后门描述的是**绕过正常入口的机制**，它可由木马或其他恶意代码安装，不必独立成一个可执行文件。[总 24–25、89–94]

## 三、计算机病毒：定义、特征与运行过程

### 1. 定义与六项特征

按课件引用的定义，病毒是破坏功能或数据、影响计算机使用且**能够自我复制**的一组计算机指令或程序代码。[病毒 4；总 4、31] 考试判别病毒时，优先抓**复制/传染性**；仅“会让系统故障”不足以判定为病毒。总册中的“广义地说，凡引起故障的程序都是病毒”是宽泛口语，不宜替代较严格的定义。[总 4、31]

课件列六项特征：[病毒 7–14；总 5、32]

1. **传染性**：自身复制、感染其他宿主，是最本质特征。
2. **寄生性**：依附于程序文件、引导区等宿主或载体。
3. **潜伏性**：感染后可暂不表现异常，有利于扩散。
4. **触发性**：日期、时间、启动、计数、特定操作等条件启动行为。
5. **非授权执行性**：在用户不知情/未授权的情况下运行。
6. **破坏性**：破坏文件或数据、消耗资源、干扰系统/网络；表现强弱不同。

总册把“寄生与隐蔽”“潜伏与触发”合并为**五组**[总 5]，病毒专题分开为**六项**[病毒 7]。问“五大特征”按总册合并写；问“主要特征”把六项全部列出，兼容两种课件表述。

### 2. 四种存在状态和三大模块

病毒可能经历**潜伏 → 感染 → 触发 → 发作**，有些样本没有明显潜伏期。[总 6、33] “感染”是扩散到新宿主；“触发”是条件满足；“发作/表现”是执行预定破坏或恶作剧。感染条件与发作条件可以不同。[病毒 12–13、18；总 33、43、50、52]

| 逻辑模块 | 主要任务 | 典型问法 |
|---|---|---|
| **引导/主控模块** | 让病毒先运行，建立环境和触发条件，必要时隐藏自身并把控制交回宿主 | “病毒怎样获得控制权？” |
| **感染模块** | 寻找目标，判断感染条件，实施复制/寄生，可能使用感染标志避免重复感染 | “怎样传播到另一个文件？” |
| **表现模块** | 判断表现条件，执行预定行为 | “什么条件下发作？” |

[总 10–11、43–53；病毒 17–24] 病毒册第 18 页将感染模块再分为“条件判断/感染实现”，表现模块再分为“触发判断/表现实现”。答结构图题可画“三大模块 + 两个子模块”。

### 3. 寄生方式与多维分类

**替代法**用病毒代码替代宿主全部或部分内容；**链接法**把病毒代码接到宿主首部、尾部或中部，尽量保持宿主运行。[病毒 9–11] 按位置可分引导区病毒、文件病毒、宏病毒以及总册列出的引导兼文件等；宏病毒寄生于支持宏执行的文档内容。[病毒 15；总 7、34–35]

其他分类维度：[总 7–9、34–42]

- **攻击目标/平台**：DOS、Windows、UNIX/Linux、手机等。
- **是否驻留内存**：驻留型将代码留在内存监视新目标；非驻留型运行时直接选择目标文件感染。
- **表现/躲避方式**：多态、变形、隐身、外壳、伴随、反杀毒等。多态/变形通过改变代码外观降低固定特征码命中率；隐身可通过拦截读请求或伪装文件信息掩盖感染。
- **破坏程度**：课件列无害、无危险、危险、非常危险四级；是课件的教学分类，不表示“无害型”就不需要处置。[总 9、42]

**引导区病毒**借启动阶段引导内容先获得执行机会，替换/迁移正常引导程序并试图维持系统启动；**PE 文件病毒**利用 Windows 可执行文件格式感染其他 PE 文件，常使宿主仍能运行以减少暴露。[总 12–13、54–59、61–62] 考试主要解释“**感染位置与为何会先执行**”，不必背老式 BIOS 中断地址或具体感染代码。课件有些引导区、Windows 95/98 与旧 PE 操作细节属于历史环境，不等同于所有现代系统的启动路径。

## 四、病毒发现、检测与防护

### 1. 检测方法及限制

**异常现象**如运行慢、崩溃、文件损坏、重启或屏幕异常可提示调查，但也可能由硬件、配置或其他故障造成；不能仅凭症状确诊病毒。[病毒 26]

| 方法 | 依据 | 主要局限 |
|---|---|---|
| 文件长度检测 | 感染后文件尺寸异常变化 | 不追加长度、压缩或伪装长度时会漏报；正常更新也会变化 |
| 感染标志/病毒签名检测 | 某病毒写进宿主的特殊标记 | 并非所有病毒都有固定标志；标志可变/可伪造 |
| 特征代码扫描 | 在样本中查已知字节序列 | 对新变种、多态/变形样本可能失效 |
| 校验和/哈希比较 | 与可信的原始基线比对文件内容 | 基线若已被感染或被篡改，结果无意义；只能指出变化，未必指出原因 |
| 行为监视、进程监视 | 关注异常复制、篡改、持久化和网络行为 | 有误报，也可能被隐藏手段绕过 |
| 软件模拟/沙箱、深入分析 | 在隔离环境观察、反汇编分析 | 需要资源和专业判断；恶意样本可能识别分析环境 |

[总 15、63；病毒 27–31] 课件第 27 页问“长度检测法有什么局限性”，直接答：**文件未增大时漏检，文件正常增大时误判，不能准确识别所有病毒**。第 30 页的校验和法能发现**相对于可信基线的未知改动**，但“发现改变”不等于“证明改变一定是病毒”。

病毒“签名”在课件第 28 页可能指**感染标记**，第 29 页“特征代码”指扫描用字节模式；两者不要与软件发布者的**数字签名**混为一谈。[病毒 28–29]

### 2. 防护分层

课件给出**最小特权、最少开放服务、慎用未知软件和邮件附件、适当使用写保护、反病毒技术**。[病毒 31–34] 实际复习可按“预防—发现—遏制—恢复”答：

- **预防**：及时更新系统和应用，减少暴露服务，按最小权限运行，可信来源安装，限制宏和未知可执行内容。
- **发现**：反病毒扫描、行为监控、日志、文件完整性基线。
- **遏制**：发现可疑主机后按组织流程隔离，避免继续传播并保护证据。
- **恢复**：清除/重装受损组件、恢复可信备份、检查凭证与其他主机。

安装杀毒软件和防火墙**不能保证绝不感染**：新变种、未修补漏洞、钓鱼/社会工程、配置错误和已获授权程序的滥用均可能突破单一防线。[病毒 44]

## 五、蠕虫、木马、陷门与其他恶意代码

### 1. 蠕虫：独立且主动传播

蠕虫是独立恶意程序，通常借网络连接、漏洞或弱点主动复制到其他主机。课件重点特征是**独立性、传播反复性、主动性**；危害可包括资源消耗、监视或破坏。[总 16–18、60]

三大功能模块：[总 17、65–70]

1. **传播模块**：探测可传播对象、利用弱点、把自身复制到新主机。
2. **隐藏模块**：伪装进程/服务、减少可见痕迹。
3. **目的模块**：完成控制、监视或破坏等目标。

课件第 67 页的扫描策略（减少重复探测、分散时间、选择网段）用于理解蠕虫为何能更快扩散/更难被发现；防御思路是补丁与漏洞管理、限制横向连接、网络监测、隔离感染端点。[总 18、67] 不要把“任何会在网络上传输的病毒”都自动叫蠕虫，关键是**独立主动复制**。

### 2. 木马：欺骗性植入与受控行为

木马通常不靠自身复制传播，靠伪装附件、捆绑安装、手工投放或被其他恶意程序带入；受害端程序可与攻击者的控制端组成 C/S 关系。[总 19–23、75、78–82]

- **配置程序**：给受害端程序设置参数；**控制程序**：攻击者端发送命令、接收数据；**木马服务端程序**：留在受害系统执行控制指令。[总 21、80–81]
- **可造成的行为**：监视、取走信息、执行命令、文件/注册表修改、键盘/屏幕窃取等。[总 20、77–79、86]
- **隐藏/持久化**：进程与文件伪装、捆绑正常程序、启动项、服务项等。`Win.ini`、`System.ini`、`Winstart.bat` 是课件历史 Windows 示例，考试记“启动配置/服务持久化”即可。[总 22、83–84]
- **连接方式**：课件列正向、反向、反弹连接。判题要抓**谁主动建立网络连接**；反向连接由受害端主动连向控制端，可绕开部分只限制入站的网络配置，但不表示所有防火墙必然失效。[总 23、85]

### 3. 陷门/后门

陷门是未登记的秘密入口，使攻击者可绕过正常认证步骤、维持再次进入能力；可位于账户、网络服务、文件系统、共享库、计划任务、内核或启动区。[总 24–25、89–94] 课件列“改密码后仍可进入”是**某些后门保留独立入口**的例子，非所有后门的普遍性质。`rootkit` 常用于隐藏进程/文件/系统变更，但**rootkit 与后门不完全同义**：前者偏隐藏与维持控制的工具集合，后者强调秘密入口。

### 4. 其他类型

- **逻辑炸弹**：满足指定条件才执行恶意动作。
- **细菌（rabbit/bacteria）**：自复制并大量消耗系统资源。
- **间谍软件**：秘密收集信息；**下载器/启动器**：获取或启动其他载荷；**勒索软件**：限制数据可用性并索取赎金；**僵尸网络**：多台受控设备组成控制网络。[总 26、29、95–96]
- **广告软件、Cookie/网络臭虫**在课件“其他”中出现，但普通 Cookie 本身是 Web 状态机制，**不是天然恶意代码**；是否恶意要看未经授权的跟踪、欺骗或其他行为。[总 26、96]

## 六、缓冲区溢出：从内存布局到防护

### 1. 五类内存区域与栈帧

课件用 C 程序的概念图分为**代码段、已初始化数据段、BSS（未初始化全局/静态数据）、堆、栈**。堆供动态内存分配；栈保存函数局部变量和调用相关数据，如返回地址、参数等。[溢出 2–7] 图中的地址高低排列是教学示意，具体布局随平台、编译器及运行环境而异。

在课件的 32 位 x86 栈例中：`ESP` 指栈顶、`EBP` 指向栈帧基址附近、`EIP` 指下一条要执行的指令。函数调用会保存返回地址；函数结束时若该地址被破坏，程序返回的位置可能异常。[溢出 12–23] 这是理解后果的关键，**不必把每张动画栈图的字节位置当成通用布局**。

### 2. 什么是溢出？为什么会发生？

缓冲区是存放数据的一块有容量的内存区域；**缓冲区溢出**是写入超过容量，越界数据覆盖相邻内存。[溢出 8–10] 例如 `char buf[8]` 只有 8 字节，若把 8 个可见 ASCII 字符当作 C 字符串复制，还需第 9 个**终止符 `\0`**，已超过容量。是否产生可利用后果还取决于布局和运行条件。

典型漏洞链：[溢出 9–11、21–24、33]

1. 存在固定大小的目标缓冲区。
2. 写入/复制操作没有正确验证目标容量，或长度计算出错；课件以 `strcpy`、`strcat`、`gets` 等旧 C 接口说明风险。
3. 输入长度或内容可由外部控制。
4. 越界数据覆盖普通变量、控制数据或返回地址，造成错误结果、崩溃、拒绝服务，严重时改变控制流。

**“函数名危险”只是提醒**：根本问题是容量、边界和输入长度没有正确关联。使用有长度参数的接口也必须传入正确容量并处理字符串终止、整数溢出等问题。[溢出 24、33–34]

### 3. 课件三种攻击空间示意

课件用 `NSR`、`RNS`、`RS` 比较**恶意数据放哪里、被改写的返回地址指向哪里**：[溢出 27–32]

| 课件简称 | 教学情形 | 应理解的空间关系 |
|---|---|---|
| `NSR` | 脆弱缓冲区较大 | 输入区本身有空间容纳额外载荷；越界改写控制数据后可能跳回输入区 |
| `RNS` | 脆弱缓冲区较小 | 输入区不足以容纳全部载荷，需借其他可控位置存放；仍利用越界影响返回路径 |
| `RS` | 载荷放在环境变量中 | 输入区主要用于改变控制数据，载荷在另一块可控内存中 |

考试重点是**共同前提：可控越界写入 + 重要控制数据被覆盖**。课件中的 Shellcode、NOP 填充和 32 位栈地址是老式演示，真实系统还可能受随机化、不可执行内存与控制流保护影响；不要背具体地址、字节串或将演示代码当作通用方法。[溢出 27–32]

### 4. 分层防御

课件从**程序员、编译器、用户**三方总结：[溢出 34]

- **开发阶段**：校验输入长度与目标容量，使用有明确边界的安全 API，正确处理末尾终止符；对长度运算做溢出检查，审查 C/C++ 中不安全的复制与拼接。
- **编译/运行阶段**：采用栈保护、地址空间随机化、不可执行数据页、控制流完整性等缓解机制，降低错误被利用的可能；这些机制不能替代修复代码。
- **部署阶段**：及时更新和打补丁，以最低必要权限运行服务，减少暴露面，监控异常崩溃与重复试探。

**简答题模板**：“原因：未检查边界，外部输入写超过缓冲区；机理：覆盖邻近数据或栈上的返回地址，造成崩溃/控制流劫持；防范：安全编程和边界检查、编译/运行时保护、补丁与最小权限。”[溢出 9–11、23–24、33–34]

## 八、病毒册第 44 页四道思考题

1. **主要特征？** 传染、寄生、潜伏、触发、非授权执行、破坏；其中自我复制/传染是最关键的区别点。[病毒 7–14、44]
2. **有哪些隐藏技术？** 寄生在合法程序/引导区；更换/加壳/变形代码规避固定特征；截获读请求伪装文件内容或大小；伪装进程/服务和启动项；条件触发、延迟发作以减少暴露。答题可按“文件/代码层、运行层、表现时机”归纳。[总 8、40、68、83–84；病毒 12、44]
3. **装了最新版杀毒软件和防火墙就一定不会感染吗？** **不能保证**。特征库可能未覆盖新样本，软件或系统可有漏洞，用户可被诱骗运行程序；防火墙侧重网络流量，不能替代文件、终端和账户保护。需要更新、最小权限、可信来源、备份与监测配合。[病毒 31–34、44]
4. **管理局域网怎样防病毒入侵？** 建资产清单并修补漏洞；限制不必要服务、共享和横向访问；统一终端防护与特征/行为检测；邮件与下载过滤、移动介质管理、最小权限；网络分段、异常流量监测；定期备份并演练隔离与恢复；教育用户识别不可信附件和安装包。[病毒 33–34、44；总 16–18、60–70]

## 九、考前自测

1. 一段代码藏在文档宏中，运行后把自身复制到其他文档：优先归哪类？若它作为独立进程主动扫描网络主机，又体现哪类特征？
2. “木马不能自复制”是否等于“木马不可能由蠕虫带到另一台机器”？说明理由。
3. 比较感染标志、特征代码、文件校验和：分别检查什么，哪种方法依赖可信基线？
4. `char buf[8]` 能否安全容纳长度为 8 的 C 字符串？为什么？
5. 为什么栈上局部缓冲区越界写入可能使函数返回异常？
6. 一台主机正常通过防火墙，但被安装程序暗中加入远程控制组件，应从“预防、发现、遏制、恢复”四方面如何处理？

**答案**：1. 首先是宏/文件病毒；独立主动网络传播则体现蠕虫特征，可兼有。2. 不能；木马本身不自传播，但可被蠕虫或其他下载器投放。3. 感染标志是病毒留在宿主上的标记；特征代码是用于扫描的已知字节模式；校验和比较当前文件与可信原始版本，依赖基线。4. 不能；8 个可见字符还需 `\0`，共 9 字节。5. 邻近的栈控制数据包括保存的返回地址，越界覆盖后返回路径可能错误。6. 限制不可信安装、监测异常进程/连接、隔离主机并保全证据、清理或恢复可信镜像及凭证。

## 十、最后记忆卡与课件辨析

- **病毒**：寄生、自复制；“潜伏—感染—触发—发作”；“引导—感染—表现”三模块。[总 4–15；病毒 4–24]
- **蠕虫**：独立、主动经网络传播；传播模块含探测/利用/复制，另有隐藏与目的模块。[总 16–18、60–70]
- **木马**：欺骗/被植入、通常不自传播、受控；配置端—控制端—受害端程序；后门是秘密入口。[总 19–25、75–94]
- **缓冲区溢出**：输入超容量 → 越界覆盖 → 数据/控制流异常；栈帧中关注返回地址；防线是边界检查、编译运行保护、及时修补。[溢出 8–34]
- **课件易错点**：总册把“红色代码”列为多态病毒例子，[总 8、40] 但微软将 Code Red 明确称为**蠕虫**：[微软历史安全公告](https://learn.microsoft.com/en-us/security-updates/securitybulletins/2001/ms01-044)。不要仅据此把蠕虫与病毒混为一类。木马“必须靠人植入”、装防火墙即可挡住木马、或特征码一定能发现病毒，都是过度概括。部分 DOS、旧 Windows 引导和栈地址示意只用于解释原理，不是所有现代系统的行为。[总 16、60、82；溢出 12–32]
