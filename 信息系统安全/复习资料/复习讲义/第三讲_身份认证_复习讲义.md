# 第三讲复习讲义：身份认证

> 依据：`03《信息系统安全》第三讲 身份认证-d-all.pptx`，126 页。文件名为“第三讲”，封面写作“第四讲”；本讲义按文件名与实际主题归入第三讲。页码均指这份 PPT。本文覆盖课件正文、比较图、Kerberos 时序、全部明确练习题及课堂讨论问题。个别课件表述不严谨时，分别标明“课件答案”和需要补充的条件。

## 一、本讲主线 [3—21、126]

开放网络中，系统不能仅凭用户自称的身份授予服务。**身份认证**检验“你是不是你声称的那个人”；通过认证后，**授权/访问控制**再决定“你能做什么”；**审计**记录“你做了什么”。[6、9—10、15—16]

整个技术路线可按四层复习：**认证因素 → 口令与 OTP → 生物特征 → 密码协议（签名、证书、Kerberos）**。课件末尾再引出双因素、多因素和新技术。[17—21、121—126]

## 二、基本概念与认证因素

### 1. 认证、消息认证、授权、审计 [7、9—16]

| 概念 | 要回答的问题 | 常见凭据或结果 |
| --- | --- | --- |
| 身份识别 Identification | “你声称是谁？” | 用户名、账号、身份标识。 |
| 身份认证 Authentication | “你确实是这个身份吗？” | 口令、令牌、生物特征、证书、票据。 |
| 授权 Authorization / 访问控制 | “这个身份可以访问什么？” | 角色、权限、资源和操作限制。 |
| 审计 Audit | “事后能否查明做了什么？” | 日志、操作记录。 |
| 消息认证 Message authentication | “消息来源可信、内容未被改动吗？” | MAC、数字签名等。 |

用户名通常完成**识别**，密码用于**认证**。指纹有时同时用于识别与认证。[15] 认证通常先于授权，但“已登录”不等于“有权读取所有文件”。消息认证针对报文，身份认证针对实体；二者在协议中可能结合。[7、16]

### 2. 三类认证因素 [17—19、45]

1. **你知道的（知识因素）**：口令、PIN、秘密问题。
2. **你拥有的（占有因素）**：智能卡、硬件令牌、USB Key、已绑定的设备。
3. **你固有的（生物因素）**：指纹、人脸、虹膜等生理特征，也可包括声纹、签名、步态、按键节奏等行为特征。

因素分类看的是**证明依据**，不是输入界面。手机上输入的 PIN 仍是知识因素；手机里的认证器若靠独立种子生成 OTP，手机/令牌是占有因素。两个口令仍属同一类因素，不能因为输入两次就称为双因素。[17—19、121]

**双因素认证（2FA）**至少使用两类不同因素，例如“静态口令 + 动态令牌”或“静态口令 + USB Key”。多因素认证（MFA）泛指使用两类或更多独立因素。课件第 123 页把 MFA 写成“至少三种”，这是较窄的用法；后续答课件问法时说明其原文，讨论通用概念时以“至少两类因素”为准。[121—124]

## 三、静态口令、攻击与一次性口令

### 1. 口令的优点与缺陷 [22—29]

口令部署简单、成本低，但弱口令、重复使用、泄露、社会工程、嗅探、暴力猜测和重放会削弱其安全性。[23—29] 课件区分“口令（用户记住的字符串）”和“密码学技术（对数据进行变换的算法与密钥体系）”。日常把登录口令叫“密码”可以理解，概念题要看上下文。[22]

**嗅探攻击**通过观察网络通信获取凭据或敏感数据；**重放攻击**即使不破解或修改旧消息，也可重新发送先前有效的认证报文或签名订单，使缺乏新鲜性检查的系统再次接受。[26—28] 防重放通常要让认证消息绑定**时间、随机挑战、序号或一次性使用状态**，并检验有效期。[27—28、99、119]

### 2. OTP、HOTP 与 TOTP [29—40]

**一次性口令（OTP）**随动态因子变化，意图使截获的旧口令不能长期重复使用。典型生成关系可记为：`OTP = 基于共享密钥 K 和动态因子的密码运算结果`。[30—32]

| 类型 | 动态因子 | 同步要求 | 常见问题 |
| --- | --- | --- | --- |
| HOTP | 双方维护的计数器，通常随认证事件递增 | 计数器一致或允许有限范围的重新同步 | 多按令牌、漏用口令会使双方计数不同。 |
| TOTP | 从当前时间计算出的时间步长 | 时钟和时间窗口足够接近 | 时钟偏移、窗口切换、密钥丢失。 |

课件有时用“事件同步”概括 HOTP；核心是**计数器随事件变化**。[32、35] TOTP 的概念式是 `T = floor((当前时间 − 起始时间) / 时间窗口长度)`，双方用相同密钥、算法与 T 生成口令。课件练习采用**128 位密钥、30 秒窗口**；密钥长度和时间窗口是题设，不代表所有网站都必须如此。[40—44]

**SecurID**是课件中的时间同步令牌例子，包含生成动态码的令牌和验证服务器。手机认证器属于软件令牌的一种。[33—37] OTP 能减轻旧口令重放风险，但仍可能遭实时钓鱼、中间人转发、设备丢失或共享密钥泄露。部署时还要考虑成本、使用负担和同步问题。[38—40]

课件第 31 页的 `MD5(用户名＋密码＋时间)` 只是用来说明“加入动态因子”的示意式，不能当作规范的 TOTP 实现。课件将 Shannon 的一次一密与 OTP 放在同页，两者名字相似，但**一次一密的加密密钥**与**一次性登录口令**并非同一机制。[31]

### 3. TOTP 四道原题 [41—44]

题设相同：Alice 使用 Google Authenticator，网站的共享密钥长 128 位、时间窗口 30 秒；她希望使用另一个生成器。

1. **第 41 页：能否由已经生成的一次性口令恢复密钥？** **课件答案：不能。** 一次性口令是密钥和时间步长经密码运算后得到的短值，观察少量口令无法倒推出高熵共享密钥。不能靠“复制显示出的 6 位数字”完成新设备长期迁移。
2. **第 42 页：能否在第二个生成器中手动添加相同密钥？** **课件答案：可以。** 前提是 Alice 能通过可信的导出、重新绑定或原始配置途径取得该密钥，并安全导入第二个生成器。“不知道密钥”与“手动添加密钥”不能同时成立；题目的准确理解是不能从旧 OTP 反推密钥，但可在**另外获得密钥**后迁移。导入过程会把密钥交给第二个设备，应保护导入通道。
3. **第 43 页：两个生成器时间戳不同会影响口令吗？** **课件答案：会。** 更精确地说，若两者落在**不同 30 秒时间窗口**，会得到不同口令；时间虽有几秒差异但仍在同一窗口时，通常生成相同口令。验证服务器也可能允许有限时间偏差。[40、43]
4. **第 44 页：怎样在第二个生成器中得到相同口令？** 导入**相同共享密钥**，使用**相同算法、位数和时间步长配置**，使两个设备落在**同一时间窗口**。课件写“调整到相同时间”，实际要求是时间步长一致，不必每一秒完全相同。[40、44]

## 四、生物特征认证 [45—56]

**生理特征**包括指纹、手形/掌纹、静脉、虹膜、视网膜、人脸等；**行为特征**包括签名、声纹、步态和按键节奏。[45—49] 系统一般经过采集、提取特征、保存模板、比对、按阈值作出通过/拒绝决定。生物识别是概率性匹配，使用便利性与误接受、误拒绝风险需要权衡。[46、49—50、124]

课件的比较图从**普遍性、唯一性、稳定性、可采集性、准确性、可接受性、安全性和设备成本**评价各种特征。[49] 不要把图中某种技术的“高/低”当作永久不变的排名；考试更可能要求解释为何虹膜、视网膜、指纹、人脸、声纹在采集方便、用户接受度和防伪难度上不同。[48—50]

**攻击面**包括：假指纹或深度伪造的人脸/声音、偷取或篡改模板、绕过传感器直接提交旧比特串、重放、传感器侧信道、内部人员滥用和社会工程。[52、56] 课件特别指出指纹系统若不保护采样设备到服务器的传输，仍可能遭重放。[52] 对策应按攻击位置匹配：活体检测对抗展示攻击；加密和访问控制保护模板；挑战应答与安全通道防旧样本重放；审计及其他独立因素降低单点失效。[56]

**案例题：视频会议中的 AI 换脸诈骗。** 应先核实视频身份与付款指令是否来自真实授权人，再通过独立渠道回拨、多人复核和支付审批验证；单凭画面或声音不能证明付款请求可信。[4] 这是“身份认证”和“授权操作”必须连起来分析的例子。

## 五、密码学基础、签名与机密性 [57—70]

| 工具 | 核心关系 | 在本讲的用途 |
| --- | --- | --- |
| 对称加密 | 通信双方使用同一共享密钥加密与解密 | Kerberos 的票据和会话密钥。 |
| 公钥密码 | 公钥可公开，私钥由持有者保密；两者满足算法规定的数学关系 | 加密、签名、证书。 |
| 哈希/消息摘要 | 把任意长度数据映射为固定长度摘要 | 检查消息是否改变，作为签名输入。 |
| 数字签名 | 签名者用私钥产生签名，验证者用相应公钥验证 | 身份、来源、完整性及抗抵赖的证据。 |

上述是课件第 58—62 页的抽象概念。具体算法并非都能“公钥加密、私钥解密”或“私钥加密、公钥解密”：**签名不是把明文用私钥加密**；签名算法与公钥加密算法的用途和流程应区分。课件的“私钥加密哈希值”是教学简化说法。[59、61、67]

### 1. 签名与加密的区别 [63—69]

发送方 Alice 对消息计算摘要并生成**数字签名**；接收方 Bob 用 Alice 的公钥验证签名与消息是否匹配。签名主要证明**消息未被改动、签名者持有对应私钥**，不能单独保证内容不被旁观者读取。[65—67]

若还需要**机密性**，Alice 应将消息及签名放入对 Bob 保密的加密通信中。课件使用“再用 Bob 公钥加密整包”解释组合思路；现代实际协议通常用公钥机制建立或保护会话密钥，再由对称加密传送大量数据。[68—69]

判断题：

- 用 **Alice 的私钥签名**，Bob 用 **Alice 的公钥验证**。
- 对 **Bob 保密传输**，使用 Bob 的公钥体系或双方协商出的会话密钥，Bob 的私钥不得交给 Alice。
- 只知道公钥不能证明“公钥一定属于 Bob”；这引出证书和 CA。[70]

### 2. 中间人攻击如何出现 [70]

攻击者 M 把自己的公钥冒充 Bob 的公钥发给 Alice。Alice 若不验证公钥归属，就可能把本应发给 Bob 的信息加密给 M；M 解密、阅读或篡改后再转发。**解决重点是可靠绑定“身份 ↔ 公钥”**，而不是单纯增加加密次数。受信任的 CA 签发证书是一种实现途径。[70—72]

## 六、PKI、X.509 与网站证书验证 [71—97]

### 1. PKI 组成与证书生命周期 [71—85]

**PKI（公钥基础设施）**是管理公钥、身份绑定和数字证书的一套组织与技术框架，不是单个加密算法。[71—75]

- **CA 证书认证机构**：验证申请材料后签发、更新、撤销和管理证书；用 CA 私钥为证书签名。[72、76—78]
- **RA 注册机构**：受理注册、核验申请者身份并向 CA 提交请求。[76—79]
- **证书库/目录**：保存和提供证书、相关公开信息；完整 PKI 还可有密钥备份恢复、撤销处理与应用接口。[76—77、88]
- **根 CA / 中间 CA**：形成信任层级，客户端需沿证书链验证到自己信任的根。[82]
- **撤销**：证书有效期未结束也可能因私钥泄露等原因失效，课件介绍了证书撤销列表 CRL。[80、83]

**数字证书**把主体身份、公钥、颁发者、有效期、序列号、算法和扩展信息等放在一起，由 CA 签名。[73、90] X.509 是证书格式和验证框架相关标准。课件第 87 页谈到 ASN.1，这是**描述证书数据结构**的方式，本身不是加密算法。[86—90]

### 2. 验证证书时检查什么 [83、90—91]

1. 证书链签名能否验证到**受信任的根 CA**，证书有无被篡改。
2. 证书是否在有效期内，是否已被撤销。
3. 访问的**网站域名是否与证书声明的身份匹配**。
4. 密钥用途、扩展和策略限制是否允许当前用途。
5. 网站在后续握手中能否证明它掌握与证书公钥对应的私钥。

“证书是公开、可复制的”并不影响验证；关键是攻击者不能在不掌握合适私钥的情况下伪造可信签名和完成相应证明。[91] 也不能认为“有任意 CA 公钥就可确认任意网站”：CA 必须处于可信链中，且其他检查必须通过。

### 3. USB Key、USB Token 与私钥保护 [92—94]

课件对两种名称给了较固定的“静态/动态口令”对照，但实际产品的叫法和功能并不统一。考点应抓住**私钥或令牌种子是否可导出、设备是否要求本地解锁、是否产生动态口令、丢失后能否吊销**。证书可以公开，重点要保护的是相应**私钥**；把证书放在 U 盘中并不自动保证私钥安全。[92—94]

## 七、Kerberos 认证协议 [98—120]

### 1. 参与者、密钥和票据 [99—110]

Kerberos 使用可信第三方 **KDC** 和对称密钥，让客户端在分布式环境中访问多个服务，而无需把明文口令反复发给各服务器。KDC 包含 **AS（Authentication Server，认证服务器）**和 **TGS（Ticket-Granting Server，票据授予服务器）**。[99、101、108、120]

| 符号 | 含义 | 谁能使用 |
| --- | --- | --- |
| `Kc` | 客户端与 AS 关联的长期密钥，课件说由用户口令导出 | 客户端、AS。 |
| `Ktgs` | TGS 的长期密钥 | AS/TGS 等 KDC 组件。 |
| `Ks` | 目标服务 S 与 KDC 共享的长期密钥 | TGS、服务 S。 |
| `Kc,tgs` | 客户端与 TGS 的会话密钥 | 客户端、TGS。 |
| `Kc,s` | 客户端与服务 S 的会话密钥 | 客户端、服务 S。 |
| `TGT` / `Ticket_tgs` | 向 TGS 申请后续服务票据的票据 | 由 TGS 解开并核验。 |
| `Ticket_s` | 访问**指定服务 S**的票据 | 由服务 S 解开并核验。 |
| `Authenticator` | 客户端用对应会话密钥制作的认证符，含时间信息 | 接收方核验其新鲜性。 |

**TGT 不是服务票据。** 用户可在 TGT 有效期间向 TGS 请求多个服务的票据；每个服务票据通常只对应指定服务。客户端无需也不能解密给 TGS 或服务端看的票据内部内容。[111—115]

### 2. 六步消息流程 [111—118]

```text
① C → AS：请求 TGT，声明客户端和 TGS。
② AS → C：把 Kc,tgs 等信息放进由 Kc 保护的回复；附上由 Ktgs 保护的 TGT。
③ C → TGS：提交 TGT、目标服务 S 和用 Kc,tgs 保护的新认证符。
④ TGS → C：返回 Kc,s 和由 Ks 保护、供访问 S 使用的 Ticket_s。
⑤ C → S：提交 Ticket_s 和用 Kc,s 保护的新认证符。
⑥ S → C：核验后提供服务；需要双向认证时，S 用 Kc,s 返回证明。
```

核心逻辑：AS 先确认客户端并让其取得 TGT；TGS 凭 TGT 颁发某个服务的票据；服务端凭自己的长期密钥和认证符确认客户端。**时间戳、有效期和认证符的新鲜性**帮助抵抗旧消息重放。[111—118]

课件的电影院类比指出三个问题：明文出示口令、旧票可重复使用、访问多个服务要反复出示口令。Kerberos 用加密票据、有效期/认证符和 TGT 缓解这些问题。[103—110]

### 3. 优势、限制和易错点 [110、119—120]

优势是减少口令在网络上的暴露、支持单点登录、在需要时支持双向认证，并使已获票据的服务验证不必每次再查询 KDC。[99—100、110] 限制包括对 KDC 的信任和可用性依赖、长期密钥保护、时钟同步，以及跨管理域与部署运维的复杂性。[119] 时钟偏差容忍值由部署配置决定，不把课件所举数字当作普适规则。

**原题：**第 116 页问 Kerberos 的主要目的，选 **C：实现身份认证**；加密是实现手段之一。第 120 页问 AS 的含义，选 **A：Authentication Server**。[116、120]

| PPT 页 | 问题 | 作答关键 |

| 41—44 | 四道 TOTP 迁移与时间同步题 | 不能由 OTP 恢复种子；安全导入相同种子；时间步长、算法和位数必须一致。 |
| 65—69 | 签名后信息会不会外泄？ | 只签名不能保证机密性，需再建立对接收方保密的加密通信。 |
| 70 | 如何防止冒充 Bob 公钥的中间人攻击？ | 可靠验证公钥与 Bob 身份的绑定，例如验证 CA 签发的证书链。 |
| 95 | 公钥和私钥各做什么？ | 公钥可公开用于加密或验签；私钥保密用于解密或签名，具体取决于算法。 |
| 96—97 | 浏览器如何用证书验证网站？ | 验证可信链、域名、有效期、撤销与用途，并确认服务器持有对应私钥。 |
| 103—107 | 电影院类比有什么缺陷？ | 明文口令、旧票重用、多个服务重复出示凭据。 |
| 116 | Kerberos 的主要目的？ | C：身份认证。 |
| 120 | AS 是什么？ | A：Authentication Server。 |

**第 95 页证书题示范答案：** 公私钥由相关算法成对生成。公钥可公布，使他人验证签名或向持有者加密；私钥只由持有者保管，用于产生签名或解密。两者在数学上对应，但从公钥实际推得私钥应在所选安全参数下不可行。CA 把公钥与申请者身份绑定并签发证书。[59、71—73、95]

**第 96 页浏览器题（第 97 页给出课件回答）示范答案：** 浏览器收到服务器证书后，验证证书链、域名、有效期、撤销与用途；握手时服务器证明持有对应私钥，双方再建立会话密钥保护后续通信。校验失败时浏览器给出风险提示。课件提到“绿色锁标志”和“用证书中的公钥和私钥加解密数据”，属于教学简化或旧界面描述；**服务器私钥不会放进证书，也不会交给浏览器**。[83、90—97]
