# 第八讲：计算机取证技术概论——复习讲义

> 依据《第八讲 计算机取证技术概论》53 页课件整理。文中 `[P12]` 表示原 PPT 第 12 页。先掌握“**授权界定范围 → 识别与保护 → 采集并验证 → 在副本上分析 → 保存、报告**”这一条主线，再记证据位置、工具和课堂题。

## 一、考点地图

1. **定义与目的**：计算机取证/电子取证、电子证据，计算机在案件中的三种角色，证据可靠性与可用性。[P4–10]
2. **流程与原则**：范围授权、现场记录、易失性数据优先、写入保护、逐位镜像、工作副本、完整性校验、证据保存和报告。[P12–15、18、34–40]
3. **潜在证据**：计算机文件四类、文件元数据、数码相机、手机、移动介质、网络设备与办公设备；按设备特性选择采集方式。[P19–32]
4. **工具**：硬盘拷贝/写保护、手机信号屏蔽、EnCase、X-Ways、FTK、F-Response 等的用途。[P27–28、36–37、41–49]
5. **课堂题**：证据收集的首要问题、取证目标、Hash 的含义，以及“还有哪些数字设备”的讨论题。[P32、50–52]

## 二、定义、目标与电子证据

### 1. 什么是计算机取证？

课件综合定义：**对可能成为法庭认可证据的计算机及相关设备中的数据，进行确认、保护、提取、分析与归档，并以可靠、可说明的方法呈现结论的过程**。[P7–9、12] 它是计算机技术与法学交叉的工作；核心不是“找到一份文件”本身，而是能说明**文件从何处来、如何取得、是否保持完整、它能证明什么、结论有哪些限制**。

计算机在案件中可能是：①被入侵的**目标**；②实施行为的**工具**；③保存相关记录的**载体**。同一设备可能兼有多种角色，决定了要寻找哪些记录。[P5]

**电子证据**是与案件有关、以电子或数字信息形式存在的材料。课件列出数字证据、网络证据、虚拟证据、多媒体证据、电子物证等相关称谓。[P10] 回答时注意：聊天记录、日志、照片、位置记录是潜在证据；仅有数字文件不自动说明其内容真实，也不自动说明某个特定人实施了操作。需要结合来源、时间、账户、设备和其他证据核实。

### 2. 证据为什么必须可追溯？

电子数据易复制、修改，外观上未必留下明显痕迹。[P38–40] 因而应维护**证据保管链**：记录谁在何时、何地、依据何种授权接触了何物，如何封存、交接、采集、计算校验值、保存与分析。原始载体和首份取证镜像应尽量减少接触；分析在工作副本上做。[P14、39] 美国国家标准与技术研究院（NIST）对数字取证的概述也强调合法权限、保管链、数学验证、可重复性与报告：[NIST 数字取证定义](https://csrc.nist.gov/glossary/term/digital_forensics)。

**司法鉴定**是运用专业知识对诉讼中的专门性问题作检验、鉴别和判断；计算机司法鉴定的技术部分属于计算机取证。[P13] 考试答“计算机取证”和“司法鉴定”关系即可，具体证据资格与程序应以案件适用的授权和程序为准。

## 三、取证流程：按顺序理解每一步

课件列出的六个环节是：获取基本信息、制作司法鉴定复件、获取易失性数据、查找并清除恶意代码、分析司法鉴定复件、撰写取证分析报告。[P12] 课件另强调“**尽可能优先提取易失性数据**”[P14]，因此实际顺序须按设备状态和数据易失程度调整；下列流程便于答综合题。

1. **确认授权和范围**：依据搜查令或其他有效授权，明确设备、账户、时间段、数据类型及限制；了解案件细节、硬件、软件、网络/云服务环境。[P18]
2. **记录现场与设备状态**：拍照、登记设备及外设、连接状态、屏幕、时间、序列号、运行/关机状态；记录所有人员与操作。[P34]
3. **确定采集优先级**：运行中的系统先评估内存、当前进程、网络连接/流量等易失性数据，避免关机后丢失；关闭状态设备优先防止启动带来的写入。是否先采内存还是先做磁盘镜像，要结合授权、目标与损失风险决定。[P12、14、22、26]
4. **保护原始载体并采集**：能离线读取的磁盘使用写保护设备/只读方式；准备干净的**目标存储介质**，制作逐位镜像并记录介质参数、工具、操作时间与异常。[P14、34–35]
5. **验证并封存**：计算原始采集流/来源与镜像的哈希值，核对一致性；妥善保存原件与首份镜像，建立工作副本供分析。[P38–40]
6. **在副本上检查与分析**：搜索文件、日志、删除数据、时间线和相互关系，验证解释，记录可重复的步骤与不确定性。[P14、20–24、38–39]
7. **形成报告**：写清授权范围、方法、工具版本、采集与校验结果、证据定位、分析过程、发现和限制；归档证据及保管记录。[P12、39–40]

**注意三种“副本”**：原始设备/介质是证据来源；**取证镜像**尽可能完整保留内容及元数据；**工作副本**用于反复检验。课件建议保留两份完整取证拷贝，一份安全封存、一份分析。[P39]

## 四、取证原则与易错细节

课件第 14 页的五条原则可概括为：[P14]

1. **尽量不改变目标证据**；读取磁盘时使用“只读锁”或写保护设备。
2. **先考虑易失性数据**，如内存和当前网络数据包。
3. **在逐位、逐字节的镜像/工作副本上分析**，避免在原盘上反复实验。
4. **用于承接证据的目标存储器先清理/检查**，避免旧数据污染采集结果。[P35]
5. **对提取物做完整性与来源验证并记录**。课件写“所有提取文件都要经过签名”；考试可写数字签名/哈希校验及记录，但**哈希值本身不是数字签名**：前者用于比较内容，后者还涉及签署者与密钥身份。

“绝不对目标设备有任何改动”是保护目标，**活体取证在技术上往往无法做到零改动**：采内存可能需要在内存中运行工具，开机系统的日志也会继续更新。应在授权范围内选择最小影响的方法，记录必要改动和局限，不能为了追求字面“零改动”直接丢失易失性证据。[P14、22；NIST 数字调查技术评述](https://nvlpubs.nist.gov/nistpubs/ir/2022/NIST.IR.8354.pdf)。

课件流程中的“查找并清除恶意代码”[P12] **不能理解为在原始证据上直接删改**。取证阶段先识别、保存与记录恶意代码及相关痕迹；需要处置受害系统时另依处置目标操作，保持原件与镜像可复核。**“洗盘”只用于承接镜像的目标盘，绝不能清零待取证原盘。**[P14、35]

### 哈希、镜像和校验值

设原始采集内容为 `D`，镜像为 `D'`，计算 `H(D)` 与 `H(D')`。相同哈希是二者内容一致的强证据，但不证明数据在采集前真实，也不能单独证明某人做了某事；还需可信采集过程和保管链。[P40]

课件第 40 页提到 CRC、MD5。**CRC 是检错码，不是抗篡改的密码学哈希**；MD5 具有已知碰撞问题。复习时记住“采集前后计算并比较校验值”的课堂原理；实践中选择经认可的安全哈希、记录算法，并可按规范使用不止一种算法。SWGDE 的数字证据采集建议要求采集哈希、验证哈希及保管记录：[SWGDE 数字证据采集最佳实践](https://www.swgde.org/wp-content/uploads/2025/07/2025-06-30-Best-Practices-for-Digital-Evidence-Collection-18-F-002-2.0.pdf)。

**逐位镜像**能包含文件系统空闲区、未分配空间等可能遗留数据；普通“复制可见文件”通常不能完整保留这些内容及相关元数据。[P14、24、34–40] 但固态硬盘、云存储、RAID、移动设备等环境的采集限制不同，不能把“拆盘逐位镜像”当作任何设备的唯一方法。[P35 注]

## 五、潜在证据：按来源与位置记忆

### 1. 计算机系统中的四类数据

| 类别 | 课件例子 | 可能证明什么 |
|---|---|---|
| 用户创建的文件 | 邮件、图片、音视频、文档、电子表格、数据库、地址簿、日程表 | 内容、联系人、计划、交易、通信 |
| 用户保护/隐藏的文件 | 压缩、加密、密码保护、隐藏文件，含糊命名文件 | 被有意保护或隐藏的信息；不能仅因隐藏即推定违法 |
| 操作系统产生的文件 | 日志、配置、备份、临时/交换文件、缓存、Cookie、历史记录 | 操作轨迹、程序运行、访问痕迹 |
| 其他磁盘区域 | 删除文件、未分配空间、空闲区、隐藏/其他分区、系统区 | 可能残留已删内容或结构信息 |

[P20–24] **文件元数据**也要收集：创建、修改、访问/移动/删除相关时间，所有者、权限、路径等。时间戳须结合时区、设备时钟、文件系统行为及复制/同步过程解释；单个时间戳不应直接等同于行为发生时间。[P22]

**不能只搜“当前可见的文件”**：课件提醒系统临时数据、备份、删除空间中也可能有线索；但恢复出的碎片需要确认来源、完整性和关联性。[P23–24]

### 2. 设备类型与特有风险

- **数码相机**：照片、视频、音频及时间日期信息；注意元数据可能被编辑，需与原始介质及其他记录核对。[P25]
- **手机/PDA**：通讯录、通话与短信、语音信箱、邮件、文档、日程等；注意电源、网络连接与远程变更风险。课件以便携式取证箱和信号屏蔽箱示例说明采集与隔离。[P26–28]
- **移动硬盘/存储卡**：保存可见文件及可能的删除数据；介质可断电保存，但是否可恢复删除内容受覆盖和设备管理机制影响。[P29]
- **网络设备**：路由器/交换机配置、日志、网络身份信息；无线接口与连接关系也是线索。必要时记录当前运行状态和网络拓扑。[P30]
- **打印机/复印机/扫描仪/传真机**：作业记录、时间、缓冲区、网络配置及可能的本机存储。[P31]
- **其他数字设备**：监控设备、录音笔、可穿戴设备、智能家居/物联网传感器、车载终端、云服务账户等。课件第 32 页讨论题可举这些例子，并说明各自可能保留的日志、时间、位置或内容。[P19、32 注]

**确定范围的答题模板**：先看授权与案件事实，再看系统性质、设备状态和可能证据位置，最后按易失性、价值、采集成本排序；不要无边界采集与案件无关的数据。[P18–19、32]

## 六、现场收集、保存与工具

### 1. 课件现场收集六步

课件第 34–35 页给出一种**可拆卸磁盘的传统计算机**收集方法：[P34–35]

1. 记录系统硬件、软件配置。
2. 检查内部存储设备，避免静电和强磁场等物理损伤。
3. 确认要收集的内置/外置介质。
4. 记录硬盘品牌、型号、容量、接口以及其他硬件。
5. 在受控条件下取得必要配置数据。
6. 如适宜，拆下介质并由预先准备的取证系统读取。

它**不是所有案件必须照做的固定顺序**。课件注释列出的例外包括 RAID、难拆的笔记本和网络存储；对它们可能需要现场/远程方式，并完整记录方法、影响与限制。[P35 注] 目标取证存储介质应提前清洁与确认，不得与原始证据盘混淆。[P35]

### 2. 保存与复核

保存不仅是“把文件放起来”，还要避免未授权访问、误改、病毒污染和介质损坏。封存原件与首份镜像，给分析人员工作副本；保留镜像创建日志、设备参数、时间、操作者、哈希值与交接记录。案件持续时间长时，要选择可靠介质并定期核验归档件。[P38–40]

**完整性校验的边界**：哈希不同说明采集结果或内容发生差异，必须调查；哈希相同支持“该两份字节内容一致”，但证明证据价值还需解释来源、采集方法与案件关联。[P40]

### 3. 工具按功能分类

| 工具/设备 | 课件中的用途 | 复习关键词 |
|---|---|---|
| 硬盘拷贝机、写保护设备 | 采集介质镜像并尽量防止源盘写入 | 只读、镜像、校验 |
| 手机信号屏蔽箱 | 降低分析时外部无线信号对手机状态的影响 | 隔离远程通信、记录状态 |
| EnCase、X-Ways Forensics、FTK | 证据镜像处理、文件/注册表/删除数据分析与报告 | 综合取证软件 |
| F-Response | 在一定条件下远程访问运行中系统并采集 | 活体/网络取证、易失性数据 |
| 硬件加速器 | 加速特定分析任务 | 辅助工具，不能替代证据保全 |

[P27–28、36–37、41–49] 不必背广告式“全球第一”或具体拷贝速度；**要会把工具和取证任务对应起来**。工具生成结果也应验证和记录，不能因为出自某知名工具就自动可信。课件“传统工具”还提到审计策略与注册表信息提取，这些属于操作系统痕迹分析的例子。[P42]

## 七、课堂练习题答案

1. **[P32] 现场还可能有哪些数字设备？** 可答监控摄像头/NVR、录音笔、车载记录仪、智能手表、门禁系统、物联网传感器、云服务账户。给出设备后补一句潜在证据，例如监控设备的视频和时间戳、门禁的刷卡日志、车载设备的位置轨迹。[P32 注]
2. **[P50] “在计算机取证中，最重要的是？”** 课件选项 A 收集、B 分析、C 保护、D 报告。按本讲原则选 **C：保护证据**。因为原始证据若遭改变或丢失，后续分析和报告的可靠性就失去基础。[P14、38–40、50]
3. **[P51] “计算机取证的典型目标？”** 选 **C：保证证据能被使用**。具体要通过合法范围、完整性、可追溯的保管链及可说明的分析支持使用；不等于“收得越多越好”。[P9、18、51]
4. **[P52] 取证中的 Hash 是什么？** 选 **B：文件的数字指纹**。更准确地说，是对一定字节内容计算出的摘要；可比较采集前后的一致性。它**不是加密算法、攻击方式或网络协议**。[P40、52]

## 八、考前自测

1. 写出计算机在案件中的三种角色，各举一个可能产生的证据。
2. 一台计算机正在运行，内存里可能有尚未保存的会话信息；应如何处理“先关机做镜像”与“先采易失性数据”的冲突？
3. 区分原始盘、取证镜像、工作副本；“洗盘”适用于哪一个？
4. 原盘和镜像的哈希相同，能够证明什么？不能单独证明什么？
5. 某路由器及打印机都接入案发网络，各自可能提供哪类线索？
6. 为什么对 RAID、网络存储、手机不能机械照搬“拆下硬盘接拷贝机”的流程？

**自测答案**：1. 目标可留下入侵日志；工具可留下操作命令/运行痕迹；存储器可保存相关文件。2. 在授权范围内评估优先采集内存/连接等易失性信息，记录该操作带来的改变，再保护磁盘并镜像；依状态决定顺序。3. 原始盘是来源，镜像是保全复制件，工作副本供分析；“洗盘”仅用于承接数据的**目标盘**。4. 支持两份字节内容一致；不单独证明来源真实、行为人身份或案件关联。5. 路由器可有配置、网络身份与日志；打印机可有作业记录、时间和缓存。6. 数据可能依赖阵列关系、网络服务或移动设备专有接口，拆解会损坏、丢失状态或无法读取，须选合适方法并记录限制。

## 九、最后记忆卡

- **定义**：确认、保护、提取、分析、归档可用于证明事实的电子数据；可靠性取决于来源、完整性、方法和保管链。[P7–10]
- **范围**：授权先行，结合案件、设备和环境确定重点。[P18]
- **次序**：现场记录 → 评估易失性 → 保护原件 → 采集镜像 → 哈希验证 → 副本分析 → 报告归档；运行中设备按具体情况调整。[P12、14、34–40]
- **四类计算机证据**：用户创建、用户保护、系统生成、其他磁盘区域；别漏元数据。[P20–24]
- **设备**：计算机、相机、手机、移动介质、网络设备、办公设备及新型智能设备。[P19、25–32]
- **三道选择题**：第 50 页 **C**，第 51 页 **C**，第 52 页 **B**。[P50–52]
